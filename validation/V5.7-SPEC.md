# V5.7 acceptance — ModelRouter rename

V5.7 changes the public name and Skill ID from Model Auto Router / `model-auto-router` to ModelRouter / `modelrouter`. Routing policy and the V5.6 measurement boundary remain unchanged.

## Required behavior

- The portable Skill directory, frontmatter name, UI prompt, install examples, release archive and unpacked root use `modelrouter`.
- Public pages use **ModelRouter for Codex** where a qualifier helps distinguish unrelated same-name projects. Explicit Skill invocation is `$modelrouter`.
- The optional installer detects one positively identified legacy `model-auto-router` Skill, backs it up, installs `modelrouter`, replaces the legacy managed AGENTS block with the current block, then atomically retires the legacy Skill outside the active Skill directory on the same volume.
- Dry-run reports whether a legacy Skill exists without writing or deleting anything.
- If both current and legacy Skill directories exist, installation refuses the ambiguous upgrade before backups or writes.
- The installer scans both `AGENTS.md` and `AGENTS.override.md`. Multiple managed blocks, mixed old/new blocks, or a managed block in an inactive guidance file are refused before writes.
- Legacy unmarked guidance is preserved and reported for manual inspection.
- The migration does not edit model configuration, permissions, billing, account state, prompts or outcome records.
- Existing V5.6 state remains valid data. Documentation recommends the new `modelrouter-state` path; migration of user state must preserve events and occur only inside an authorized private Codex home.
- Historical release notes may retain the old name where they describe an old version. Current executable paths and public install instructions must not use the legacy Skill ID.

## Verification

- Installer unit tests cover legacy Skill and managed-marker migration, backup, cleanup, ambiguous duplicate refusal, rollback and idempotent current installs.
- Repository validation, Skill metadata validation, installed manifest verification, full regression suite, installer dry-run and unpacked release verification pass.
- Release verification uses explicit temporary user/Codex homes and normalizes local source, temporary and user paths before publishing logs.
- A real user-scope upgrade verifies that only the new Skill directory remains, the managed AGENTS block uses current markers, unrelated AGENTS content is preserved, and model configuration is unchanged.
- The previous empty local metrics state is moved to the new state path and remains readable with zero fabricated events.

Local checks do not establish exclusive rights to the ModelRouter name, publisher identity, live automatic activation, model dispatch or token savings.
